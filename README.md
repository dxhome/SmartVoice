# SmartVoice

SmartVoice is an early-stage, local speech-to-text (STT) and text-to-speech (TTS) service. It brings both tasks behind one HTTP API, with a replaceable inference backend and a model catalog for offline use.

> **Project status:** Prototype / active development. The current vertical slice has been smoke-tested on Windows x64 with CPU inference. It is not yet a packaged installer or a production release. GPU acceleration and macOS, Linux, and Android support are planned, not currently delivered.

## Why SmartVoice?

Local speech tools often require separate runtimes, model formats, and APIs for recognition and synthesis. SmartVoice aims to provide one stable interface while allowing the inference engine and device runtime to evolve behind it.

- **Local and private:** inference runs on the machine after models are installed; the service defaults to loopback and does not log request text or audio.
- **STT and TTS together:** transcribe audio and synthesize speech through the same local service.
- **Multilingual goal:** SmartVoice aims to support multilingual STT and TTS. Language coverage is declared per task, model, and voice; the current prototype catalog represents only its present implementation stage.
- **Backend boundary:** callers use the versioned HTTP API and capability response, not backend-specific SDKs or model file layouts.
- **Model integrity checks:** catalog downloads use fixed HTTPS sources and pinned SHA-256 values, with archive path and size checks.
- **Agent-friendly API:** OpenAPI documentation is generated by the service. The audio endpoints follow common OpenAI Audio API conventions for easier integration; compatibility is a supported subset, not a claim of full compatibility.

## Current implementation

| Area | Current status |
|---|---|
| Platform | Windows x64 source-run prototype; broader platform packaging is future work |
| Inference | sherpa-onnx adapter, CPU provider only |
| STT | SenseVoice Small INT8: Chinese, English, Cantonese, Japanese, Korean |
| TTS | Melo VITS ONNX: Chinese and English; WAV output |
| API | OpenAPI/Swagger UI, file transcription, speech synthesis, model/catalog and runtime status |
| Model management | List and install catalog models from fixed HTTPS URLs; no GUI yet |
| GPU | Not enabled in the current release |
| Streaming | Not exposed as a SmartVoice API yet |

The listed language and model capabilities describe the current catalog entries; they do not imply equal quality across languages. Models and their bundled assets have separate licenses. Review each model's included license before use or redistribution. SmartVoice code is licensed under Apache-2.0.

## Quick start (Windows x64)

Requires Python 3.11 or newer. This prototype runs on CPU and does not require a GPU or CUDA installation.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[inference]"
.\.venv\Scripts\python.exe -m smartvoice models list
.\.venv\Scripts\python.exe -m smartvoice models install sensevoice-small-local
.\.venv\Scripts\python.exe -m smartvoice models install melo-tts-zh-en-local
.\.venv\Scripts\python.exe -m smartvoice --host 127.0.0.1 --port 8000
```

The first model install requires internet access. Once the model files are installed, transcription and synthesis run locally without a network connection. Model weights are stored outside the repository in the user data directory (`%LOCALAPPDATA%\SmartVoice` by default); set `SMARTVOICE_HOME` to use another location.

`models list` prints a readable summary by default. Add `--json` when piping catalog output to scripts.

The model archives are downloaded from fixed HTTPS URLs declared in [`catalog/models.json`](catalog/models.json). SmartVoice checks each archive against its catalog SHA-256, validates archive paths and size limits, and records installed file hashes. The current pinned hashes were captured from the tested HTTPS archives; upstream does not publish independent checksums for these archives, so review catalog changes carefully.

## API

Start the service, then open [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) for interactive OpenAPI documentation.

| Endpoint | Description |
|---|---|
| `GET /health` | Process liveness and version |
| `GET /ready` | Readiness; reports missing required models |
| `GET /v1/capabilities` | Installed task, language, and model capabilities |
| `GET /v1/runtime` | Backend, requested/actual device, runtime status |
| `GET /v1/models` | Installed models |
| `GET /v1/catalog` | Models available from the built-in catalog |
| `POST /v1/audio/transcriptions` | Transcribe an uploaded audio file (`multipart/form-data`) |
| `POST /v1/audio/speech` | Synthesize text to WAV (`application/json`) |

The server binds to `127.0.0.1` by default and rejects non-loopback binding in this prototype. Remote/LAN access is not enabled until authentication and access controls are implemented.

### Transcribe audio

```powershell
curl.exe -F "file=@sample.wav" -F "language=zh" `
  http://127.0.0.1:8000/v1/audio/transcriptions
```

Supported upload formats include WAV, MP3, M4A, and FLAC. The default upload limit is 25 MiB and the maximum audio duration is 10 minutes. See `/docs` for optional fields and response formats.

### Synthesize speech

```powershell
curl.exe -X POST http://127.0.0.1:8000/v1/audio/speech `
  -H "Content-Type: application/json" `
  -d '{"input":"你好，SmartVoice。","language":"zh"}' `
  --output speech.wav
```

The current TTS model supports Chinese and English and returns mono WAV audio. Audio input is processed in memory; inference requests do not write uploaded audio to disk, and request bodies are not logged.

## Architecture

```text
Client / Agent
      │
      ├── Versioned HTTP API (OpenAPI)
      └── Optional future streaming/MCP adapters
                 │
      SmartVoice API and domain contracts
          ├── Model catalog and local model storage
          ├── Inference port (stable backend interface)
          └── Platform/device adapters
                 │
          sherpa-onnx adapter (current)
```

The API/capability contract is intended to remain stable while inference backends and platform providers change. Current code includes an inference port and a sherpa-onnx adapter; additional runtime and platform adapters are future work. The first release target is Windows. macOS, Linux, Android, GPU providers, streaming, and MCP integration are on the roadmap; they should not be treated as supported today.

## Development

Install the inference and development dependencies:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[inference,dev]"
```

Run the test suite:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Real-inference tests require the catalog models to be installed. To evaluate speech-recognition quality on a local reference set, copy [`examples/stt-reference-manifest.csv`](examples/stt-reference-manifest.csv), add `audio_path,reference,language` rows, then run:

```powershell
.\.venv\Scripts\python.exe examples/evaluate_models.py stt-reference-manifest.csv
```

This reports Chinese CER and English WER. Set quality thresholds using a licensed, representative corpus and reference hardware before describing a model as verified.
