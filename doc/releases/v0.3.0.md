# SmartVoice v0.3.0

SmartVoice v0.3.0 brings the full SmartVoice workflow into a new web Console and makes generated speech easier to use by returning MP3 audio by default.

## Highlights

- **New SmartVoice Console.** Use `/console` to try speech recognition and synthesis, browse and manage models, adjust Smart Router priorities, and get API examples—all through the browser UI. Routing changes can be saved directly in the Console and take effect immediately.
- **TTS returns MP3 by default.** Generated speech now plays and downloads as mono MP3 at 96 kbps by default. WAV remains available for applications that need it. The Console plays the generated audio and downloads it in the selected format.
- **Transcribe long recordings without splitting them yourself.** SmartVoice now handles recordings up to the existing 10-minute limit as one request, joining the results and preserving available timestamps.
- **More control over speech.** Supertonic long text is handled automatically, and its 10 voice choices are available in the Console.
- **More reliable cancellation under load.** Canceling or disconnecting a request stops later work without making a still-running model call appear available to another request.

## Breaking changes

- `POST /v1/audio/speech` now defaults to `response_format: "mp3"` instead of WAV.
- For direct-model STT requests with `language: "auto"`, long segmented results may return `language: null` if the model reports different or unknown languages across parts of the recording.

## Migration

- If a client expects WAV, send `"response_format": "wav"`. Clients should also use the response's `X-Audio-Format` header when selecting a file extension.
- Treat the STT `language` field as nullable for long auto-language requests. If your application needs a single language decision, provide an explicit language or use `model: "smartvoice-auto"` with `language: "auto"`.
